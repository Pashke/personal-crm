# Личная CRM

Список людей, которых я знаю лично: кто это, откуда знакомы, телефон, почта и заметки о разговорах.

## Запуск

Нужны Docker Desktop, Node.js 20.9+ и pnpm.

### 1. База данных (PostgreSQL в Docker)

1. Создать файл `.env` по образцу `.env.example` и заполнить значения.
   `.env` хранит пароли и в git не попадает. Приложение берёт подключение к базе из этих же переменных.
2. Запустить базу (из папки проекта):

   ```
   docker compose up -d --wait
   ```

3. Проверить, что база работает:

   ```
   docker compose ps
   ```

   В колонке STATUS должно быть `healthy`.

Остановить базу: `docker compose stop`. Данные при этом сохраняются.

### 2. Приложение

Один раз после скачивания проекта:

```
pnpm install
pnpm db:migrate
```

`db:migrate` создаёт в базе таблицы. Повторный запуск безопасен: уже применённые изменения пропускаются.

Тестовые данные (1000 контактов с заметками) — по желанию:

```
pnpm db:seed
```

Скрипт работает только на пустой базе: если контакты уже есть, он ничего не делает.

Запуск для работы:

```
pnpm build
pnpm start
```

Запуск во время разработки (изменения в коде видны сразу):

```
pnpm dev
```

После запуска открыть http://localhost:3000. Остановить приложение — `Ctrl+C` в окне, где оно запущено.

## Как проверить, что всё работает

1. Открыть http://localhost:3000 — виден список всех контактов и их количество.
2. «Добавить контакт» → заполнить имя → «Добавить». Контакт подсвечен в списке.
3. Набрать часть имени в поиске — список сразу отфильтруется. Открыть контакт.
4. Написать заметку → «Добавить заметку» (или Ctrl+Enter). Обновить страницу — заметка на месте.
5. Открыть тот же адрес в другом браузере — те же контакты и заметки.
6. Открыть контакт → «Удалить» → в окне подтверждения «Удалить». Открылся список с уведомлением «Контакт удалён», контакта в нём нет, число контактов уменьшилось на 1.

### Пора связаться

7. Открыть контакт, у которого больше недели не было заметок (или без заметок, добавленный больше недели назад) → «Изменить» → в «Как часто общаться» выбрать «Раз в неделю» → «Сохранить». На странице контакта строка «Как часто общаться»: «Раз в неделю · пора было N дней назад» (или «пора сегодня»).
8. Открыть главную. Над поиском блок «Пора связаться», в нём этот контакт: «раз в неделю · последний раз N дней назад» или «ещё не общались». Сверху самые просроченные, сразу видны первые три. Если контакта среди них нет — нажать «Показать всех», он будет ниже. «Свернуть» снова оставляет первых трёх.
9. Нажать на этот контакт в блоке, написать заметку → «Добавить заметку». Строка «Как часто общаться» сразу показывает «следующий раз до …» — через неделю от сегодня. Вернуться на главную — контакта в блоке больше нет.
10. У другого контакта в блоке нажать галочку справа («Уже связался»). Под строкой открылось поле заметки, страница контакта не открылась. Ничего не писать, нажать «Сохранить». Контакт ушёл из блока, вверху уведомление «Заметка сохранена» с кнопкой «Отменить». На странице контакта первая заметка — «Связались».
11. С ещё одним контактом из блока сделать то же самое, но в течение 5 секунд нажать «Отменить» в уведомлении. Контакт вернулся в блок на своё место, на его странице заметки «Связались» нет.
12. Набрать имя в поиске — блок «Пора связаться» скрыт. Очистить поиск — блок снова виден.

Тестовые данные (`pnpm db:seed`) задают частоту примерно трети контактов, поэтому на них блок сразу заполнен.

## Изменения схемы базы

Таблицы описаны в `src/db/schema.ts`. После правки схемы:

```
pnpm db:generate
pnpm db:migrate
```

Первая команда создаёт файл миграции в папке `drizzle/`, вторая применяет его к базе.

## Подготовка сервера (один раз)

Скрипт `deploy/server-setup/setup.sh` готовит сервер к выкатке:

- ставит Docker из официального репозитория. Порты контейнеров открываются только на 127.0.0.1, снаружи к ним не попасть. Логи контейнеров ограничены по размеру;
- создаёт пользователя `deploy`: под ним GitHub Actions выкатывает приложение. Пароля и sudo у него нет, только SSH-ключи и доступ к Docker. Доступ к Docker равен правам root, поэтому ключи берегите;
- создаёт папку приложения `/home/deploy/personal-crm`;
- ставит nginx: на whobook.ru заглушка, app.whobook.ru передаёт запросы приложению. Пока приложение не запущено, там видна страница «Приложение временно недоступно». http перенаправляется на https;
- получает один сертификат Let's Encrypt на оба домена. Продлевается сам, по таймеру `certbot.timer`.

Перед запуском DNS-записи обоих доменов должны указывать на сервер. Повторный запуск безопасен: готовые шаги пропускаются, файлы, созданные не этим скриптом, не трогаются.

Ключи для входа под `deploy` скрипт берёт из файла `deploy-authorized_keys` рядом с собой. В git этот файл не хранится, его кладут на сервер отдельно. В нём две строки: публичная часть ключа деплоя (с пометкой `restrict`: только команды, без терминала) и ваш личный публичный ключ.

Запуск из папки проекта в PowerShell (спросит пароль sudo):

```
scp -r deploy/server-setup crm:~/
ssh -t crm 'sudo bash ~/server-setup/setup.sh <почта> 2>&1 | tee ~/server-setup/setup.log'
```

После этого — один раз создать на сервере файл с паролем базы. Войти под `deploy` (`crm-deploy` — запись в `~/.ssh/config`):

```
ssh crm-deploy
```

и уже на сервере выполнить:

```
set -o noclobber; umask 077
{ echo POSTGRES_USER=crm; echo POSTGRES_DB=crm; echo "POSTGRES_PASSWORD=$(openssl rand -hex 24)"; } > ~/personal-crm/.env
exit
```

Пароль генерируется случайный и на экран не выводится. Файл доступен только владельцу (права 600). Если файл уже есть, команда его не перезапишет.

## Выкатка

Выкатка автоматическая: каждый push в `main` выкатывает новую версию на https://app.whobook.ru.

Что происходит (GitHub → вкладка Actions → Deploy):

1. GitHub Actions собирает образ приложения. Тег образа — SHA коммита. Образ кладётся в GHCR: `ghcr.io/pashke/personal-crm`.
2. GitHub заходит на сервер под `deploy`, копирует туда папку `deploy/` и запускает `deploy/deploy.sh`:
   - скачивает новый образ;
   - разовый контейнер из этого образа применяет миграции базы и завершается. Если миграции упали, новая версия не стартует, работает старая;
   - запускает новую версию;
   - smoke-проверка: `/health` должен ответить 200 и напрямую, и через nginx;
   - оставляет на сервере только образы текущей и предыдущей версии.
3. Если что-то упало, запуск в Actions красный, и GitHub присылает письмо. Сама выкатка ничего не откатывает.

Проверить после выкатки:

- в Actions последний запуск Deploy зелёный;
- https://app.whobook.ru/health показывает `{"status":"ok"}`;
- https://app.whobook.ru открывается, изменения на месте.

База на сервере своя, в Docker (контейнер `postgres` проекта `prod`). Данные хранятся в томе `prod_postgres-data` и переживают выкатки.

### Откат (только вручную)

```
ssh crm-deploy personal-crm/deploy/rollback.sh
```

Возвращает последнюю рабочую версию. Если упала последняя выкатка, это версия до неё, иначе предыдущая. Другая версия: `rollback.sh <sha коммита>`, её образ должен быть на сервере. Изменения базы откат не отменяет: старая версия работает с текущей базой.

### Полезные команды

```
ssh crm-deploy personal-crm/deploy/compose.sh ps                   # что запущено
ssh crm-deploy personal-crm/deploy/compose.sh logs --tail 100 app  # логи приложения
ssh crm-deploy cat personal-crm/state/current-version              # какая версия работает
ssh crm-deploy personal-crm/deploy/compose.sh run --rm seed        # тестовые данные (только в пустую базу)
```

### Настройки в GitHub

Settings → Secrets and variables → Actions:

- секрет `DEPLOY_SSH_KEY` — приватная часть ключа деплоя;
- переменные `DEPLOY_HOST` (адрес сервера), `DEPLOY_USER` (`deploy`), `DEPLOY_KNOWN_HOSTS` (отпечаток сервера: так GitHub убеждается, что подключился именно к нему).
