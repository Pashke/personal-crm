# Spec Delta

## MODIFIED Requirements

### Requirement: Готовые группы

Пять групп «Семья», «Друзья», «Знакомые», «Теннис», «Аналитики», в таком порядке, SHALL быть только у владельца данных, которые были до появления входа. Это обычные группы: их можно переименовать и удалить. Контакты, добавленные до фичи групп, MUST остаться без групп, их данные и заметки не меняются. Новый пользователь MUST начинать без групп.

#### Scenario: Первая выкатка
- **WHEN** выкатывается версия с этой фичей
- **THEN** на странице «Группы» у владельца пять групп в порядке «Семья», «Друзья», «Знакомые», «Теннис», «Аналитики», и в каждой «нет контактов»

#### Scenario: Контакты, добавленные до фичи
- **WHEN** выкатывается версия с этой фичей, а в базе уже есть контакты с заметками
- **THEN** ни один из них не состоит в группах, их поля и заметки не изменились

#### Scenario: Новый пользователь без групп
- **WHEN** новый пользователь впервые входит
- **THEN** у него на странице «Группы» - «Групп пока нет», на главной нет ряда групп

### Requirement: Название группы

Название группы SHALL быть от 1 до 50 символов; пробелы по краям обрезаются. Двух групп с одинаковым названием без учёта регистра букв MUST NOT быть у одного пользователя; у разных пользователей названия могут совпадать. Проверка MUST выполняться на сервере, и для подменённых запросов тоже.

#### Scenario: Пробелы по краям
- **WHEN** пользователь создаёт группу с названием «  Коллеги  »
- **THEN** группа сохраняется с названием «Коллеги»

#### Scenario: Пустое название
- **WHEN** пользователь пытается создать группу с пустым названием или из одних пробелов
- **THEN** группа не создаётся, и показано «Укажите название группы»

#### Scenario: Слишком длинное название
- **WHEN** пользователь пытается создать группу с названием из 51 символа
- **THEN** группа не создаётся, и показано «Слишком длинное название»

#### Scenario: Такая группа уже есть
- **WHEN** на странице «Группы» пользователь добавляет «теннис», а группа «Теннис» у него уже есть
- **THEN** новая группа не создаётся, и показано «Такая группа уже есть»

#### Scenario: Такая группа есть у другого пользователя
- **WHEN** пользователь B добавляет «Теннис», а группа «Теннис» есть только у пользователя A
- **THEN** у B создаётся своя группа «Теннис», группа A не меняется

### Requirement: Новая группа из формы контакта

В поле «Группы» SHALL быть возможность ввести название новой группы: она сразу появляется в форме отмеченной, а создаётся только при сохранении контакта, и контакт в неё попадает. За раз можно завести несколько групп. Название уже существующей группы этого пользователя (без учёта регистра) не создаёт новую, а отмечает существующую.

#### Scenario: Новая группа при сохранении
- **WHEN** в форме «Новый контакт» пользователь заводит группу «Коллеги» и сохраняет контакт
- **THEN** группа «Коллеги» есть на странице «Группы» последней, и контакт в ней

#### Scenario: Две новые группы
- **WHEN** пользователь заводит в форме «Коллеги» и «Соседи» и сохраняет контакт
- **THEN** созданы обе группы, и контакт состоит в обеих

#### Scenario: Отмена формы
- **WHEN** пользователь завёл в форме группу «Коллеги» и нажал «Отмена»
- **THEN** группы «Коллеги» нет

#### Scenario: Название существующей группы
- **WHEN** пользователь вводит в форме «теннис», а группа «Теннис» у него уже есть, и сохраняет контакт
- **THEN** новая группа не создаётся, контакт состоит в «Теннис»

#### Scenario: Название чужой группы
- **WHEN** пользователь B вводит в форме «Теннис», а группа «Теннис» есть только у пользователя A, и сохраняет контакт
- **THEN** у B создаётся своя группа «Теннис», контакт в ней, в группе A контакта нет

#### Scenario: Неверное название
- **WHEN** пользователь вводит в форме пустое название или длиннее 50 символов
- **THEN** группа не заводится, и показано то же сообщение, что на странице «Группы»

### Requirement: Проверка групп контакта на сервере

При сохранении контакта сервер SHALL записывать ему только существующие группы этого же пользователя. Группу, которую удалили, пока была открыта форма, MUST молча пропускать: контакт сохраняется с остальными группами, без ошибки. Так же пропускается подменённое значение, которое не указывает на существующую группу пользователя, в том числе номер чужой группы.

#### Scenario: Группу удалили, пока открыта форма
- **WHEN** в одной вкладке открыта форма контакта с отмеченными «Друзья» и «Теннис», в другой удалили «Теннис», а в первой нажали «Сохранить»
- **THEN** контакт сохранён и состоит только в «Друзья», ошибки нет

#### Scenario: Подменённое значение
- **WHEN** в запросе сохранения контакта вместо группы прислано значение, которое не указывает на существующую группу
- **THEN** контакт сохранён без этого значения, с остальными отмеченными группами

#### Scenario: Чужая группа
- **WHEN** пользователь B присылает сохранение своего контакта с номером группы пользователя A
- **THEN** контакт B сохранён без этой группы, в группе A контакта B нет

### Requirement: Ссылка «Группы» в шапке

В шапке каждой страницы приложения после входа рядом с «Личная CRM» SHALL быть ссылка «Группы», которая открывает страницу «Группы».

#### Scenario: Переход на страницу «Группы»
- **WHEN** пользователь на главной или на странице контакта нажимает «Группы» в шапке
- **THEN** открывается страница «Группы»
