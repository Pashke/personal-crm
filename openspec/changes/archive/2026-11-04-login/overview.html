Вход по ссылке и свои данные

Каждый входит под своей почтой по ссылке из письма — без пароля — и видит только свои контакты, заметки и группы. Всё, что уже есть в базе, становится вашим.

1Коротко

  • Без входа приложение не открывается: любой адрес ведёт на страницу входа. Там поле почты и кнопка «Получить ссылку».
  • На почту приходит письмо с кнопкой «Войти». Ссылка срабатывает один раз и живёт 15 минут. Первый вход и есть регистрация — паролей и анкет нет.
  • Вход держится 30 дней с последнего захода на устройстве. Можно сидеть сразу с компьютера и телефона. «Выйти» — только на этом устройстве.
  • У каждого контакта и каждой группы появляется владелец. Чужое не видно и не меняется — ни на экранах, ни подменённым запросом к серверу (запрос, который отправили не из формы, а в обход неё).
  • Ваши нынешние контакты, заметки и группы станут вашими: приложение узнаёт вашу почту из строки OWNER_EMAIL в .env (файл настроек с секретами, в git не попадает).
  • Письма на компьютере и в автотестах попадают в почтовую заглушку Mailpit (программа, которая ловит письма и показывает их на своей странице, никуда не отправляя), на сервере — уходят через сервис Resend.

3Как это работает

Без входа приложение закрыто

Любая страница без входа открывает страницу входа. Запрос к серверу без входа ничего не читает и не сохраняет. Без входа открыты только страница входа, ссылка из письма, страница «Ссылка устарела» и /health (проверка, что сервер жив, — её дёргает выкатка).

Открыли без входа адрес контакта /contacts/15 → страница входа, о контакте ничего не видно.
Вход только по ссылке, первый вход — регистрация

Паролей нет. Почта, с которой ещё никто не входил, после открытия ссылки становится новым пользователем. Имя не спрашиваем. Следующие входы с той же почтой — тот же пользователь.

Почта: пробелы и регистр не важны, неверная — ошибка

Пробелы по краям убираются, большие и маленькие буквы не различаются. Сервер проверяет почту сам, даже если запрос пришёл не из формы.

После отправки всегда «Ссылка для входа отправлена на <почта>» — и для новой почты, и для знакомой. Исключения — лимит писем и сбой отправки.

Ссылка: один раз, 15 минут, новая отменяет прежние
  • Ссылка впускает один раз. Открыли второй раз — «Ссылка устарела, запроси новую».
  • Работает 15 минут с момента отправки.
  • Запросили новую — все прежние неиспользованные ссылки этой почты перестают работать.
  • Ссылку можно открыть на другом устройстве: войдёт то устройство, где её открыли.
10:00 — первая ссылка, 10:05 — вторая. Первая → «Ссылка устарела». Вторая в 10:19 → вход. Вторая в 10:21 → «Ссылка устарела».
Не больше 3 писем на одну почту за 10 минут

Считаются последние 10 минут и только письма, которые ушли. Сверх лимита письмо не уходит, а прежняя ссылка продолжает работать. Для каждой почты — свой счёт. Если почтовый сервис не принял письмо — «Не удалось отправить письмо. Попробуй ещё раз.», и эта попытка не считается.

На anna@example.com ушли письма в 10:00, 10:02, 10:04. В 10:06 — «Слишком часто…», а ссылка из письма 10:04 работает. В 10:06 на ivan@example.com письмо уходит. В 10:11 на anna@example.com — снова можно: письмо 10:00 уже старше 10 минут.
Вход держится 30 дней с последнего захода

Каждый заход продлевает срок (не чаще раза в сутки, поэтому на деле — от 29 до 30 дней после последнего захода). Не заходили 30 дней — снова страница входа. Можно быть внутри с нескольких устройств сразу. «Выйти» завершает вход только на этом устройстве.

Вошли 1 ноября, заходили 21 ноября → 16 декабря всё ещё внутри. Вошли на компьютере и телефоне, нажали «Выйти» на телефоне → на компьютере вы по-прежнему внутри.
Каждый видит и меняет только своё

Список, поиск, счётчик «Найдено N из M», блок «Пора связаться», карточка, заметки, группы, фильтр по группе — только записи вошедшего. Заметки принадлежат владельцу контакта. M в счётчике — число ваших контактов.

У A контакт «Анна Соколова». B ищет «Соколова» → «Никого не нашлось по запросу «Соколова»». У A 3 контакта, у B 2 → у B «Найдено N из 2».
Чужое — как будто его нет
  • Чужой контакт по прямой ссылке и его «Изменить» → «Контакт не найден».
  • Подменённый запрос с номером чужого контакта (изменить, удалить, заметка, быстрая заметка) → «Контакт не найден — возможно, его удалили.», контакт A не меняется. Удаление чужого контакта ничего не удаляет. Отмена чужой быстрой заметки — «Отменить уже нельзя».
  • Чужая группа: переименование → «Группа не найдена — возможно, её удалили.», удаление → ошибки нет, группа A на месте. Номер чужой группы в форме контакта молча пропускается.
У каждого свои группы

Название группы не повторяется только у одного пользователя. У A и у B может быть по группе «Друзья», у каждого со своими людьми. Ввёл в форме контакта «Теннис», а такая группа есть только у другого — у тебя создаётся своя.

Новый пользователь начинает с нуля

Пустой список с подсказкой «Добавь первый контакт», групп нет. Пять готовых групп («Семья», «Друзья», «Знакомые», «Теннис», «Аналитики») остаются только у вас.

Всё, что уже есть в базе, — ваше

Контакты, заметки, группы и состав групп получают владельца — пользователя с почтой из OWNER_EMAIL. Ни одна запись не теряется и не меняется, кроме появления владельца. Если данные есть, а почта не задана или неверная — выкатка останавливается до старта новой версии, база прежняя. Демо-данные (pnpm db:seed) тоже создаются у этого пользователя и только если у него ещё нет контактов.

Куда уходят письма — решают настройки

Одна и та же сборка приложения: на компьютере и в автотестах письма уходят в Mailpit, на сервере — через Resend. Разница только в строке SMTP_URL в настройках. Автотесты настоящих писем не шлют.

Чего не будет
  • Паролей, входа через Google и соцсети, входа по коду из письма.
  • Профиля, смены почты, удаления аккаунта.
  • Общего доступа к контактам, приглашений, ролей и админки.
  • Возврата после входа на страницу, которую открывали до входа: после входа всегда главная.
  • Списка устройств и «выйти везде».

4Модель данных до и после

Модель данных — какие таблицы лежат в базе и какие в них поля. Фича добавляет таблицы пользователей и входов, а контактам и группам — поле «чьё».

Сейчас: у данных нет владельца

Все контакты и группы общие: их видит каждый, кто открыл адрес. Название группы уникально на всю базу.

Схему можно листать вбок.

После: у контакта и группы есть владелец

Появляется таблица users — пользователи, главное в ней почта. У контактов и групп появляется поле user_id — номер пользователя-владельца. У заметок и состава групп своего поля нет: их владелец — владелец контакта.

Служебные таблицы входа

verifications

Ссылки из писем, пока ими не воспользовались. Живут 15 минут. После входа ссылка гасится, поэтому второй раз не сработает. При новой ссылке прежние ссылки этой почты удаляются.

sign_in_emails

Когда и на какую почту ушло письмо. По ней считается лимит «не больше 3 писем за 10 минут». Строки старше 10 минут удаляются.

accounts

Нужна библиотеке входа Better Auth. Паролей и входа через соцсети у нас нет, поэтому она пустует.

  • Пользователь — строка в users с почтой. Она создаётся сама, когда человек впервые открывает ссылку из письма.
  • Вход на устройстве — строка в sessions. Браузер хранит её номер в cookie (маленькая запись в браузере), по нему приложение узнаёт вас на каждой странице. Компьютер и телефон — две строки. «Выйти» удаляет только строку этого устройства.
  • Поле user_id у контактов и групп обязательное: контакт или группу без владельца база больше не сохранит. Случайно удалить пользователя вместе с его контактами база не даст.

Как запрос находит своё и не находит чужое

К каждому запросу в базу добавляется условие «и владелец — тот, кто вошёл». Пример: Иван Петров — контакт №15 у пользователя A. Оба открывают ссылку /contacts/15.

Вошёл A — anna@example.com
найди контакт №15 у anna@example.com
Нашёлся: карточка Ивана
Вошёл B — ivan@example.com
найди контакт №15 у ivan@example.com
Не нашёлся: «Контакт не найден»

Так же работают правка, удаление, заметки, быстрые заметки, группы, фильтр и «Пора связаться»: чужая запись для базы просто не существует.

Миграции

Миграция — скрипт, который меняет устройство базы. Их две. На сервере они выполняются сами, после бэкапа и до старта новой версии. Обе проходят одним куском: если вторая упадёт, отменится и первая — база останется как до выкатки.

  1. Таблицы входа старые данные не меняет

    drizzle/0004_…sql: создаёт users, sessions, accounts, verifications, sign_in_emails. Контакты, заметки и группы не трогает.

  2. Владелец для всего, что есть меняет данные

    drizzle/0005_…sql: добавляет user_id контактам и группам, записывает в него вас (как — ниже), делает поле обязательным и меняет правило групп: было «название уникально во всей базе», стало «уникально у одного владельца». SQL этой миграции я покажу вам до merge.

Как ваши данные получат владельца

Настройка

Строка OWNER_EMAIL в .env — на сервере и у вас на компьютере. В git почта не попадает.

Перед миграциями

Почта очищается от пробелов, переводится в маленькие буквы и проверяется. Неверная — миграции не начинаются. Верную настройки подключения к базе передают в миграцию.

Миграция 0005 спрашивает

В базе есть контакты или группы?

Нет ни контактов, ни групп

Ничего не делать. Бывает редко: даже в свежей базе есть пять готовых групп.

Есть, а почты нет

Ошибка. Миграции отменяются целиком, новая версия не стартует, старая продолжает работать.

Есть, почта задана

Найти или создать пользователя с этой почтой и записать его во все контакты и группы. Ваш первый вход попадёт сразу в ваши данные.

Числа для примера, похожие на сегодняшнюю базу на сервере. Перед merge я запишу настоящие числа, после выкатки сверю. Автотест миграции проверяет то же: строк до и после столько же, поля те же, у всех владелец с вашей почтой.

Откат — только вместе

Прошлая версия приложения не знает про владельцев: на новой базе она не смогла бы сохранить контакт и показывала бы всем всё. Поэтому откат этой выкатки — только вдвоём: прошлая версия приложения (rollback.sh) и база из бэкапа, снятого перед выкаткой (restore.sh). Запускаете вы, порядок будет в README.

Команда миграций остаётся прежней (drizzle-kit migrate) как раз ради отката: rollback.sh запускает миграции старой версии, а в старом образе приложения новых скриптов нет.

5Как проверить руками

Подготовка на компьютере (когда фича будет сделана): добавить в .env новые строки — какие, скажу при реализации. docker compose up -d --wait — запустятся база и Mailpit. Потом pnpm db:migrate и pnpm dev, приложение — http://localhost:3000, письма — http://localhost:8025.

Двух пользователей проверять в двух разных браузерах или в обычном и приватном окне: у каждого свой вход.

Ссылка в письме ведёт на localhost, поэтому с телефона она не откроется — вход проверяйте на компьютере.

«Будет автотест» — сценарий проверит автотест по плану. «Руками сложно» — без правки базы или подделки запроса не повторить; проверит автотест, руками можно пропустить. «Только руками» — автотеста нет. Галочки только для удобства и не сохраняются.

Продуктовые — стоит просмотреть

Записаны в proposal.md, раздел «Что я решил сам - проверьте».

  • Адрес страницы входа — /login. После входа всегда главная. Уже вошли и открыли /login — главная.
  • После отправки форма остаётся, сообщение — под ней.
  • Почта в сообщении и в шапке — без пробелов и маленькими буквами.
  • Пустое поле — та же ошибка «Проверь адрес почты».
  • Лимит считает только ушедшие письма. При лимите прежняя ссылка работает.
  • Сбой почтового сервиса — «Не удалось отправить письмо. Попробуй ещё раз.», в лимит не считается.
  • Любая негодная ссылка — одна страница «Ссылка устарела, запроси новую», кнопка «На страницу входа».
  • Ссылку можно открыть на другом устройстве — войдёт оно.
  • На странице входа в шапке только «Личная CRM».
  • «Контакт не найден» — для любого отсутствующего контакта, в том числе удалённого, и для его «Изменить». Для других адресов — прежнее «Такой страницы нет».
  • «Добавь первый контакт» — у всех, у кого пустой список, не только у новых.
  • Тексты входа на «ты», письмо на «вы», остальное приложение — как было, на «вы».
  • Нет OWNER_EMAIL при данных в базе — выкатка останавливается. Пользователь с вашей почтой создаётся при выкатке.
  • Вход продлевается не чаще раза в сутки — на деле 29–30 дней после последнего захода.
  • Не входит: возврат на страницу, открытую до входа; список устройств и «выйти везде».

Технические — на экраны не влияют

  • Better Auth 1.7.16 и Nodemailer 10.3.1 — оба названы в постановке. Better Auth 1.7.16 вышла вчера, pnpm поставит её после ~21:30 UTC сегодня; иначе спрошу про 1.7.15.
  • Каждая функция чтения и записи получает пользователя явно: забыть проверку — программа не соберётся. В запросах условие «и владелец — вошедший».
  • Запросить ссылку можно только через форму приложения: прямой путь Better Auth выключен, чтобы никто не обошёл проверку почты и лимит.
  • Отмена старых ссылок, лимит и отправка — в одной транзакции (всё или ничего) с блокировкой по почте: два одновременных запроса не обойдут лимит, а при сбое отправки старые ссылки возвращаются.
  • Файл proxy.ts продлевает вход на каждом заходе: иначе Better Auth не продлевал бы его при обычном просмотре страниц.
  • Встроенный лимит Better Auth по IP тоже работает, IP берётся из заголовка nginx. В e2e у каждого теста свой IP, чтобы тесты не делили лимит.
  • Адрес почтового сервера — одна строка SMTP_URL; отправитель noreply@mail.crm.whobook.ru одинаков везде.
  • Почту владельца в миграцию передаёт настройка подключения к базе (PGOPTIONS), команда миграций остаётся прежней — ради отката.
  • Нет каскадного удаления контактов вместе с пользователем: случайное удаление пользователя руками не сотрёт данные.
  • Mailpit v1.33.0 в Docker, только на localhost. Письма живут до его перезапуска.
  • Vitest — с настоящим Better Auth и базой, отправка писем подменена ловушкой. e2e — без подмен, с настоящей Mailpit.
